## Context

SPEC section 6 requires the smallest dedicated check that can enforce the forbidden
dependencies (A01-A03, A12) and source policies (A13, A18, A20, A21), each with a negative
test, without installing Boundary by default. Ash has no built-in layering checker, and Credo
checks one file's AST at a time, so it cannot see cross-module calls produced by macros.

## Decision

The checks are ExUnit tests in `test/architecture/` backed by one module,
`Sketch.ArchitectureCheck` in `test/support/`. For compiled code it reads the application's
BEAM files: OTP `:xref` provides remote call edges, the atom table catches module references
that are not calls, and module attributes provide declared behaviours. Source policies are
line-based scans. Negative tests compile violating fixtures into a temporary directory with
`Kernel.ParallelCompiler.compile_to_path/3` and run the same checker on them. Rules,
statuses and allowlists live in `architecture/rules.exs`.

## Alternatives considered

- **Boundary**: declarative and well known, but adds a compiler and a dependency the spec
  asks us not to install by default. Rejected unless these checks prove insufficient.
- **Custom Credo checks**: run in the existing tool, but see only per-file source, so they
  miss calls generated by macros and references across files. Rejected.
- **`mix xref graph` output parsing**: no extra code to read BEAM files, but it reports
  file-level compile/runtime dependencies rather than call targets, and the text format is
  not a stable API. Rejected.

## Consequences

The checker uses only OTP and the standard library, runs in `mix test` and CI, and every rule
has a fixture proving it fails. It sees static calls and references only; a module name
built at runtime would escape it, which code review must catch. Revisit if the number of
layers grows enough that Boundary's declarative model would be simpler to maintain.
